### 2. IS THIS THE MOST EFFICIENT SOLUTION?
Альтернативы (из research):
- **А: Native MAX polls** — недоступно через API. Отклонено.
- **Б: Create poll из Mini App** — сложнее UX (владелец должен вернуться в Mini App после публикации). Отклонено.

**Почему В лучше:** нет новых экранов, следует архитектурным паттернам (реакции, callback), минимальный код.

## Архитектурная схема

```
Владелец пишет пост с #poll
         │
         ▼
  onPostCreated.ts
  ├── parsePoll(text) → { question, options } | null
  ├── db.createPoll(postId, question, options)
  ├── buildPollButtons(postId, options, counts=[0,0,...])
  └── editMessage → кнопки опроса + кнопка Comments + реакции
         │
         ▼ (подписчик нажимает вариант)
  onCallback.ts
  ├── parse: /^poll_(\d+)_(\d+)$/
  ├── answerCallback() — немедленно
  ├── db.togglePollVote(pollId, userId, optionIdx) — транзакция
  └── editMessage (дебаунс 300мс) — обновить счётчики на кнопках
         │
         ▼ (Mini App открывается)
  GET /api/polls/:postId/results
  └── { poll: { question, options: [{text, count, percent}] }, voted_option: number|null }
         │
         ▼
  PollWidget.tsx
  └── Прогресс-бары + подсветка выбранного варианта
```

## DB миграция

```sql
-- Таблица опросов
CREATE TABLE IF NOT EXISTS post_polls (
  id          BIGSERIAL PRIMARY KEY,
  post_id     BIGINT NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  question    TEXT NOT NULL,
  options_json JSONB NOT NULL,  -- [{text: "Вариант А"}, ...]
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE(post_id)               -- один опрос на пост
);

-- Голоса
CREATE TABLE IF NOT EXISTS poll_votes (
  poll_id     BIGINT NOT NULL REFERENCES post_polls(id) ON DELETE CASCADE,
  user_max_id BIGINT NOT NULL,
  option_idx  INT NOT NULL,
  voted_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (poll_id, user_max_id)  -- один голос на пользователя
);

CREATE INDEX IF NOT EXISTS idx_poll_votes_poll_id ON poll_votes(poll_id);
```

### Фаза 3: Backend — API результатов
**Файлы:** `backend/src/routes/polls.ts` (новый), `backend/src/db/db.ts`, `backend/src/index.ts`  
**Зависимости:** Фаза 0 (типы), Фаза 1 (таблицы созданы)

**Задачи:**

**3.1 `backend/src/db/db.ts`** — добавить:
```typescript
export async function getPollResults(
  postId: number,
  userMaxId?: number
): Promise<PollResults | null>
```

SQL:
```sql
SELECT
  pp.id,
  pp.question,
  pp.options_json,
  COALESCE(
    json_agg(
      json_build_object('option_idx', pv_agg.option_idx, 'count', pv_agg.cnt)
    ) FILTER (WHERE pv_agg.option_idx IS NOT NULL),
    '[]'
  ) AS vote_counts,
  (SELECT option_idx FROM poll_votes WHERE poll_id = pp.id AND user_max_id = $2) AS voted_option
FROM post_polls pp
LEFT JOIN (
  SELECT poll_id, option_idx, COUNT(*)::int AS cnt
  FROM poll_votes
  GROUP BY poll_id, option_idx
) pv_agg ON pv_agg.poll_id = pp.id
WHERE pp.post_id = $1
GROUP BY pp.id
```

**3.2 Новый файл `backend/src/routes/polls.ts`:**
```typescript
export const pollsRouter = Router();

// GET /api/polls/:postId/results
// Публичный (optionalAuth — чтобы знать voted_option)
pollsRouter.get('/:postId/results', optionalAuth, async (req, res) => {
  const postId = parseInt(req.params.postId, 10);
  if (isNaN(postId)) return res.status(400).json({ error: 'Неверный postId' });

  const userMaxId = req.maxUser?.user_id;
  const results = await pool.query(getPollResults(postId, userMaxId));

  if (!results) return res.json({ poll: null });
  res.json(results);
});
```

## Потенциальные проблемы

| Проблема | Решение |
|----------|---------|
| editMessage после голосования — нужно знать текущий `selectedEmoji` пользователя | `getPostStateWithUserReaction` уже возвращает это — передавать вместе с pollButtons |
| Клавиатура стала длиннее (poll + реакции + Comments) | Порядок: [Comments] → [poll options...] → [реакции] — читается логично |
| parsePoll с кириллицей и эмодзи | Regex с флагом `u`, trim каждой строки |
| `#poll` без вариантов (ошибка владельца) | `parsePoll` возвращает null → пост без опроса, без ошибки |
