# ADR-003 — Найденные баги и уроки (сессии 2026-04-08–09)

> Справочник: что пошло не так, где искать, как не повторить.

---

## БАГ 1 — onBotAdded: канал не сохранялся в БД

**Симптом:** Пользователь добавляет бота в канал → нажимает «Проверить» в онбординге → «Канал не найден».

**Причина:** MAX присылает `bot_added` событие с такой структурой:
```json
{ "update_type": "bot_added", "chat_id": -70951869617414, "user": { "user_id": ... } }
```
Обработчик `onBotAdded.ts` делал `const message = update.message; if (!message) return` — и сразу выходил, потому что `message` отсутствует в `bot_added`. Поле `chat_id` находится на верхнем уровне `update`, а не внутри `update.message.recipient`.

**Фикс:** Читать `update.chat_id` и `update.user` (с fallback на `update.message`).

**Где смотреть:** `bot/src/handlers/onBotAdded.ts`, `shared/types.ts` (поля `chat_id?`, `chat_type?`, `user?` в `WebhookUpdate`).

## БАГ 2 — Кнопка «Оформить PRO» была заглушкой

**Симптом:** Пользователь нажимает «Оформить PRO» — ничего не происходит.

**Причина 1:** В `PricingPage.tsx` кнопка вызывала `alert('Оплата откроется в ближайшее время')` — TODO-заглушка, которую забыли заменить.

**Причина 2:** `alert()` в MAX Mini App **не отображается вообще** (падает молча). Поэтому казалось, что кнопка сломана.

**Фикс:** Подключить реальный `POST /api/payments/create`, открывать `payment_url` через `window.WebApp.openLink()`. Ошибки показывать через React-стейт, не через `alert()`.

**Правило:** `alert()`, `confirm()`, `prompt()` — не использовать в MAX Mini App никогда.

## БАГ 3 — TBANK env vars не попали в контейнер

**Симптом:** Переменные добавлены в `.env`, но `docker exec mc_backend env | grep TBANK` — пусто.

**Причина:** `docker compose restart mc_backend` **не перечитывает `.env`** — он просто перезапускает существующий контейнер. Переменные окружения берутся при создании контейнера.

**Фикс:** После изменения `.env` всегда делать `docker compose up -d mc_backend` (пересоздаёт контейнер).

**Правило:**
- `restart` → перезапуск процесса, env не меняется
- `up -d` → пересоздание контейнера, подхватывает новый `.env`
- `up -d --build` → пересборка образа + пересоздание

## БАГ 4 — Docker кэш не подхватывает изменения файлов

**Симптом:** Файл изменён и загружен на сервер, `docker compose up -d --build` запущен, но Docker пишет `CACHED` на шаге COPY и старый код продолжает работать.

**Причина:** Docker кэширует слои. Если контекст сборки не изменился с точки зрения Docker (например, файл загружен через SFTP, но Docker сравнивает контрольные суммы), слой берётся из кэша.

**Фикс:** Убедиться что файл реально изменился на сервере (`head -5 /opt/max-comments/backend/src/routes/payments.ts`). При необходимости принудительно сбросить кэш: `docker compose build --no-cache mc_backend`.

## БАГ 5 — autoRenew.js содержит устаревший ЮКасса-код

**Симптом:** `autoRenew.js` в dist ссылается на колонку `yookassa_id` которой больше нет в БД — упадёт при попытке вставить рекуррентный платёж.

**Статус:** Не исправлен (рекуррентные платежи T-Bank отложены). При добавлении рекуррентов — обновить `backend/src/jobs/autoRenew.ts`.

**Где смотреть:** `backend/src/jobs/autoRenew.ts`

## Общие правила диагностики

| Проблема | Где смотреть |
|----------|-------------|
| Канал не находится при проверке | Логи бота: `docker logs mc_bot --since 5m` |
| Платёж не создаётся | Логи backend: `docker logs mc_backend --since 5m` |
| Env vars не подхватываются | `docker exec mc_backend env \| grep TBANK` |
| Новый код не работает | `docker exec mc_backend grep -r 'ключевое_слово' dist/` |
| TypeScript ошибки при сборке | Смотреть вывод `#RUN npm run build` в docker build output |
| Mini App не обновился | Убедиться что mc_nginx пересобран (`--build mc_nginx`, ~3 мин) |
