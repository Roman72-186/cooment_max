# ADR-003: pg возвращает BIGINT как строку — нормализовать в Number()

**Дата:** 2026-04-08
**Статус:** Принято

## Контекст

Все первичные ключи и `max_user_id` объявлены как `BIGINT` в PostgreSQL. Библиотека `node-postgres` (`pg`) возвращает BIGINT-колонки как строки JavaScript, чтобы избежать потери точности при конвертации в 64-bit float.

Это вызвало скрытый баг: строгое сравнение `"99999" === 99999` давало `false`, из-за чего:
- DELETE-роут всегда возвращал 403
- `canDelete` на фронтенде всегда был `false`
- Кнопка удаления не отображалась

## Решение

**Правило:** при использовании BIGINT-полей из pg в JS-сравнениях — всегда приводить через `Number()`.

В API-ответах, где числа нужны клиенту для сравнения (например, `author_max_id`, `channel_owner_max_id`) — нормализовать перед `res.json()`:

```typescript
const normalized = rows.map((row) => ({
  ...row,
  author_max_id: Number(row.author_max_id),
  channel_owner_max_id: Number(row.channel_owner_max_id),
}));
res.json(normalized);
```

## Альтернативы

- Приводить через `::int` в SQL — опасно для очень больших ID (overflow INT4)
- Настроить кастомный type parser в pg — усложняет конфигурацию
- Использовать `==` вместо `===` — скрывает проблему, не решает её

## Последствия

Затрагивает все BIGINT-поля которые участвуют в сравнениях или передаются клиенту: `max_user_id`, `id`, `author_max_id`, `channel_owner_max_id`. При добавлении новых роутов — проверять типы возвращаемых полей.
