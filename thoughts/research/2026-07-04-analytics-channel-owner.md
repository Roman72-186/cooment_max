# Исследование: аналитика для владельца канала (референс — @tgTrack_bot)

Дата: 2026-07-04. Задача: понять, что нужно владельцу канала от аналитики; разобрать @tgTrack_bot («Откуда Подписки», tgtrack.ru) — что даёт и на какие боли давит; спроецировать на cooment_max.

## 1. Что такое @tgTrack_bot

Telegram-бот «Откуда Подписки» + сервис tgtrack.ru. Позиционирование: **«Как снизить стоимость подписчика в Телеграм на 30-40% за 2 недели за счёт аналитики»**. Это не «просмотрщик статистики», а инструмент оптимизации рекламного бюджета.

### Как работает технически
1. Бота добавляют админом канала (без доп. прав).
2. В боте создаётся пригласительная ссылка с параметрами: целевой пост, метка креатива, UTM.
3. Трафик с рекламы ведут на эту ссылку; бот запоминает клик и параметры, редиректит в канал.
4. Алгоритм матчит нового подписчика с кликом → атрибуция источника с точностью >95%.
5. Интеграция с Яндекс Директ/VK: передача офлайн-конверсий → «платить Яндексу только за подписки».

### Функции
- **Атрибуция**: откуда пришёл каждый подписчик (площадка → креатив → UTM), конверсия переходов в подписку.
- **Отток**: кто отписался, когда; отписки по когортам (1–7 дней, 7–30, 30+); % отписок по каждому источнику трафика.
- **Ежедневные отчёты** в DM: новые подписчики / отписки за день.
- **Полный список подписчиков** включая ушедших, распределение по давности подписки.
- **Конверсия посадочных постов** в подписку (какой пост-лендинг работает).
- **Лид-магнит бот**: выдача бонуса с проверкой подписки.
- **Выгрузка** интерактивных отчётов в Excel/Google Docs.
- **Анти-фрод**: внешние трекинг-ссылки не дают «нечестным админам» посевов подлить ботов в статистику.

### Тарифы
Free (навсегда, базовые функции; пользователи хвалят «супер-функционал даже в бесплатной») / PRO 1990 ₽/мес или 1490 ₽/мес при годовой оплате. Продающий аргумент окупаемости: «5–7 подписчиков окупят месячную подписку».

## 2. Боли владельца канала, на которые давит tgTrack

1. **«Я плачу за рекламу и не знаю, что работает»** — главная боль. Бюджет размазан по площадкам/креативам вслепую → стоимость подписчика завышена в 1,5–2 раза.
2. **«Подписчики уходят в первые дни»** — реклама приводит нецелевую аудиторию, либо контент не соответствует обещанию в рекламе. Без когортного анализа отписок причину не найти.
3. **«В посевах мне подливают ботов»** — нечестные админы каналов-доноров накручивают результат; нужна независимая внешняя статистика.
4. **«Не понимаю, какой пост конвертит»** — какой посадочный пост / формат захода даёт подписку.
5. **«Хочу платить за результат»** — оптимизация рекламных кампаний по конверсии «подписка», а не по кликам.

Из обзоров рынка (vc.ru, TGStat/Telemetr/LiveDune/Popsters) — общий список задач владельца: динамика подписчиков, охваты, ER/вовлечённость, лучшее время публикации, качество аудитории (боты/накрутки), сравнение с конкурентами, ROI рекламных интеграций.

## 3. Проекция на cooment_max (MAX)

### Что уже есть у нас
`analytics_daily` (просмотры/комментарии/реакции по дням) + топ постов, AnalyticsPage с графиками (?days=7, до 90). Это «engagement-аналитика», которой у tgTrack нет вообще — наша сильная сторона.

### Чего нет и что просят боли
Всей «подписной» аналитики: рост/отток, источники, когорты, ежедневный отчёт.

### Техническая реализуемость в MAX API
- **`chat_member_updated`** — webhook-событие «изменился статус участника чата». Ключ ко всему: лог join/leave → рост, отток, когорты отписок. Мы это событие сейчас игнорируем (default-ветка в `bot/src/webhook.ts`). Нужно проверить боем: приходит ли оно для каналов (не только групп) и что в payload.
- **`GET /chats/{id}/members`** — пагинация по 100, есть `last_activity_time` у участника → «активное ядро» и лучшее время для поста. Осторожно: rate limit 30 req/sec, большие каналы качать батчами в фоне.
- **Deep link `https://max.ru/<bot>?start=<payload>`** — единственный механизм меток. Создание инвайт-ссылок канала ботом в MAX API не найдено → атрибуция «в лоб» как у tgTrack невозможна. Возможна схема «бот-прокладка»: трекинг-ссылка ведёт на бота с меткой → бот отдаёт кнопку в канал → матчим по `chat_member_updated` в окне времени. tgTrack сам говорит, что прокладка теряет 20–50% конверсии, но в MAX альтернативы пока нет.
- **Ежедневный DM-отчёт** — инфраструктура DM уже есть (`sendNotifications.ts`), добавить job тривиально.

### Приоритеты (гипотеза, не план)
1. **P0 — рост/отток подписчиков**: слушать `chat_member_updated`, писать в БД, график «+X/−Y в день» в AnalyticsPage. Минимум усилий, закрывает боль №2 частично и даёт базу для всего остального.
2. **P0 — ежедневный DM-дайджест владельцу**: подписчики ±, комментарии, реакции, топ-пост дня. Дешёво, возвращает владельца в продукт каждый день (retention-петля).
3. **P1 — когорты отписок** (ушёл через 1–7/7–30/30+ дней) — требует истории join из п.1.
4. **P1 — engagement-метрики, которых нет у tgTrack**: ER поста (реакции+комменты/подписчики), топ-комментаторы, доля активного ядра, лучшее время активности (по `last_activity_time` и времени комментариев). Наше УТП.
5. **P2 — атрибуция источников** через бот-прокладку с метками `?start=src_<...>`. Самая сильная боль рынка, но в MAX сейчас рекламный рынок каналов только формируется — проверить спрос до постройки.
6. **PRO-гейт**: базовые графики — free, когорты/атрибуция/дайджест-настройки — PRO (модель tgTrack: щедрый free → апселл).

### Открытые вопросы
- Приходит ли `chat_member_updated` для каналов и его payload (нужен тест на живом канале).
- Отдаёт ли `GET /chats/{id}` participants_count (в нашем reference не зафиксировано).
- Есть ли у MAX нативная статистика каналов для владельцев (чтобы не дублировать, а дополнять).
