## 1. Зона: onPostCreated + onCallback

### onPostCreated.ts — как работает сейчас
- Получает webhook, читает `message.body.text` и `message.body.attachments`
- Фильтрует `mediaAttachments` (всё кроме `inline_keyboard`)
- Сохраняет пост через `db.createPost()` с `attachments_json`
- Инициализирует реакции через `db.initPostReactions()`
- Строит клавиатуру через `maxClient.buildPostKeyboard(postId, 0, reactionButtons, commentsEnabled)`
- Редактирует пост через `maxClient.editMessage(messageId, { text, attachments })`

**Ключевой момент:** текст поста полностью доступен в `message.body.text` — можно парсить `#poll`.

### onCallback.ts — как работает сейчас
- Парсит `callback.payload` regex `/^react_(\d+)_(.+)$/u`
- Формат: `react_<postId>_<emoji>`
- Немедленно вызывает `answerCallback` (fire-and-forget) до любого `await`
- Дедупликация через `recentCallbacks` Map с ключом `<postId>_<userId>_<emoji>`
- Дебаунс 300 мс для `editMessage` через `pendingEdits` Map
- Оптимистичное обновление UI без ожидания БД

**Ключевой момент:** добавление нового типа callback (`poll_<postId>_<optionIdx>`) — прямое расширение существующей ветки `if`.

### Формат inline_keyboard в MAX API
```json
{
  "type": "inline_keyboard",
  "payload": {
    "buttons": [
      [{ "type": "open_app", "text": "💬 Комментарии (5)", "web_app": "...", "payload": "post_123" }],
      [
        { "type": "callback", "text": "😀 3", "payload": "react_123_😀" },
        { "type": "callback", "text": "· ❤️ 5", "payload": "react_123_❤️" }
      ]
    ]
  }
}
```

**Для опроса:** кнопки вариантов — тип `callback`, каждая в своём ряду (для читаемости).

## 2. Зона: DB schema + maxClient

### Таблица posts — ключевые поля
- `id`, `channel_id`, `max_message_id`, `text_preview`, `attachments_json JSONB`
- `comments_enabled`, `post_reactions TEXT[]`
- `comment_count`, `last_activity_at`

### Реакции на посты (аналог для опросов)
- `post_reaction_counts (post_id, emoji, count)` — счётчики
- `post_user_reactions (post_id, max_user_id, emoji)` — PK `(post_id, max_user_id)` — **один пользователь, одна реакция**
- Транзакционный toggle в `db.togglePostReaction()` с BEGIN/COMMIT

**Прямая аналогия для опросов:**
- `post_polls (id, post_id, question, options_json)` — один опрос на пост
- `poll_votes (poll_id, user_max_id, option_idx)` — PK `(poll_id, user_max_id)` — **один голос на опрос**

### maxClient.ts — editMessage
Принимает `{ text, attachments }`. Ключевой паттерн: медиа + клавиатура объединяются в `attachments`.

## 3. Зона: Backend routes

### Паттерн нового роут-файла
```typescript
export const pollsRouter = Router();
pollsRouter.get('/:postId/results', async (req, res) => { ... });
pollsRouter.post('/:postId/vote', requireAuth, async (req, res) => { ... });
```
Регистрация в `backend/src/index.ts`: `app.use('/api/polls', pollsRouter)`.

### Auth
- `GET /api/polls/:postId/results` — публичный (без auth), результаты видны всем
- `POST /api/polls/:postId/vote` — через `requireAuth`, req.maxUser.user_id

### Транзакционный паттерн
```typescript
const client = await pool.connect();
await client.query('BEGIN');
// INSERT с ON CONFLICT DO NOTHING
await client.query('COMMIT');
client.release();
```

## 5. Альтернативные подходы

### Альтернатива А: Встроенные опросы MAX (нативные)
- **Плюсы:** нет кода, нет нагрузки
- **Минусы:** MAX API не предоставляет такого механизма. Недоступно.

### Альтернатива Б: Создание опроса из Mini App UI (отдельный экран)
- **Плюсы:** богатый UX, можно добавить много вариантов
- **Минусы:** владелец должен создавать опрос ПОСЛЕ публикации поста — сломан workflow. Требует нового экрана в Mini App. Более сложный UX.

### Альтернатива В: #poll парсинг в тексте поста (ВЫБРАННЫЙ ПОДХОД)
- **Плюсы:** натуральный workflow — пишешь пост как обычно. Следует паттерну `#button`, `#tag` из TODO. Не нужен новый экран. Встраивается в существующий `onPostCreated`.
- **Минусы:** ограниченный формат текста. Нельзя изменить опрос после публикации.

## 6. Риски и edge cases

| Риск | Митигация |
|------|-----------|
| Дублирующийся callback от MAX (отправляет дважды) | Та же дедупликация что в реакциях: Map с ключом `poll_<postId>_<userId>_<optionIdx>` |
| Race condition при параллельных голосах | `INSERT INTO poll_votes ... ON CONFLICT DO NOTHING` в транзакции |
| Пост без опроса — запрос к API | `GET /api/polls/:postId/results` возвращает `null`, PollWidget не рендерится |
| Длинный вопрос/варианты — переполнение кнопки | Обрезать вариант до 32 символов при формировании кнопки |
| Изменение опроса после публикации | Не поддерживаем (poll frozen at creation, как `post_reactions`) |
| Нагрузка при массовом голосовании | Rate limiting на `POST /api/polls/:postId/vote` — 10 req/min на IP |
| `#poll` в середине поста | Парсить только если `#poll` встречается в тексте (позиция не важна) |
| Более 5 вариантов | Ограничить: максимум 5 вариантов (иначе клавиатура не читается) |

## 7. Формат #poll

```
#poll Какой контент вам нравится больше?
🅰️ Обзоры
🅱️ Новости
🅲️ Аналитика
```

**Regex для парсинга:**
```typescript
const POLL_REGEX = /#poll\s+(.+?)(?:\n([\s\S]+))?$/im;
```

Варианты — каждый с новой строки после вопроса. Любой символ в начале (эмодзи или нет).

**Упрощённый парсинг:**
1. Найти `#poll` в тексте
2. Первая строка после — вопрос
3. Каждая следующая непустая строка — вариант
4. Минимум 2 варианта, максимум 5

## РЕКОМЕНДАЦИЯ

**Выбранный подход:** Альтернатива В — #poll парсинг.

**Почему лучший:**
1. Workflow владельца не меняется (пишет пост как обычно)
2. Архитектурно следует уже принятым решениям (#button, #tag в TODO)
3. Реализация бота — расширение существующего `onPostCreated` без новых экранов
4. Callback обработка — копипаст паттерна реакций с другим prefix
