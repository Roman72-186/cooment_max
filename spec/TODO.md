## Приоритет: ВЫСОКИЙ (⭐⭐⭐⭐⭐)

### [ ] 1. Опросы и голосования в постах
- **Что:** Владелец канала добавляет `#poll Вопрос? 🅰️ Вариант1 🅱️ Вариант2` в пост — бот автоматически прикрепляет кнопки-варианты. Голосование через нажатие кнопки.
- **Ценность:** Резкий рост вовлечённости, сбор обратной связи без внешних сервисов.
- **Где реализовывать:**
  - `bot/src/handlers/onPostCreated.ts` — парсить теги `#poll`
  - `bot/src/handlers/onCallback.ts` — обработка нажатий
  - Новые таблицы: `post_polls (post_id, question, options_json)`, `poll_votes (poll_id, user_max_id, option_id)`
  - `backend/src/routes/polls.ts` — `POST /api/polls/:postId/vote`, `GET /api/polls/:postId/results`
  - `miniapp/src/components/PollWidget.tsx` — отображение результатов
- **Риски:** Нагрузка на DB при массовом голосовании → rate limiting на эндпоинт.
- **Монетизация:** Базовый опрос — FREE, расширенная аналитика — PRO.

### [ ] 2. AI-автомодерация комментариев
- **Что:** Анализ токсичности/спама через OpenAI/YandexGPT до сохранения комментария в БД. Автоудаление при превышении порога.
- **Ценность:** Снимает нагрузку с владельцев каналов, улучшает атмосферу.
- **Где реализовывать:**
  - `backend/src/utils/aiModeration.ts` — вызов API
  - `backend/src/routes/comments.ts` — проверка перед `INSERT`
  - Новые колонки: `comments.moderation_score FLOAT`, `channels.ai_moderation_enabled BOOLEAN`, `channels.ai_threshold FLOAT`
- **Риски:** Стоимость API-вызовов (нужен бюджет), ложные срабатывания → настраиваемый порог.
- **Монетизация:** Только PRO.

## Приоритет: СРЕДНИЙ (⭐⭐⭐⭐)

### [ ] 3. Теги и категории постов
- **Что:** Парсить `#теги` из текста поста, фильтровать ленту комментариев по категориям в Mini App.
- **Ценность:** Организация контента, навигация по большим каналам.
- **Где реализовывать:**
  - Новая таблица: `post_tags (post_id, tag_name)`
  - `bot/src/handlers/onPostCreated.ts` — парсинг тегов
  - `backend/src/routes/posts.ts` — `GET /api/posts?channel_id=X&tag=news`
  - `miniapp/src/pages/InboxPage.tsx` — UI фильтров
- **Риски:** Усложнение UX — нужен хороший дизайн фильтров.

### [ ] 4. Live-чат режим для горячих постов
- **Что:** При >50 комментариев за час пост переходит в live-режим — новые комментарии появляются без перезагрузки через WebSocket.
- **Ценность:** Engagement во время событий (трансляции, розыгрыши, анонсы).
- **Где реализовывать:**
  - WebSocket сервер (`ws` пакет) в backend
  - `miniapp/src/hooks/useLiveComments.ts` — подключение к WS
  - `backend/src/routes/comments.ts` — broadcast новых комментариев
  - `bot/src/jobs/updateCounters.ts` — детект hot posts
- **Риски:** Сложность WS-инфраструктуры, нагрузка на единственный VPS.

### [ ] 5. Кастомные кнопки действий под постом (PRO)
- **Что:** Владелец добавляет `#button Купить товар https://shop.com` → кнопка появляется под постом, клики считаются в аналитике.
- **Ценность:** Лидогенерация, перенаправление трафика на сайт/магазин/лендинг.
- **Где реализовывать:**
  - Новая таблица: `post_custom_buttons (post_id, title, url, click_count)`
  - `bot/src/handlers/onPostCreated.ts` — парсинг `#button`
  - `bot/src/handlers/onCallback.ts` — счётчик кликов
  - `backend/src/routes/analytics.ts` — статистика кликов
- **Риски:** Злоупотребление (спам-ссылки) → нужна валидация URL + возможность бана канала.
- **Монетизация:** Только PRO.

## Общие технические риски (для всех фич)

- **VPS**: один сервер — при росте нагрузки нужно планировать горизонтальное масштабирование.
- **MAX API rate limit**: 30 req/sec — массовые операции (рассылки, голосования) требуют очередей.
- **Нестабильность MAX API**: молодой мессенджер, возможны breaking changes.
- **Нативные комментарии от MAX**: главная угроза — если MAX выпустит встроенные комментарии, часть ценности платформы исчезнет.
